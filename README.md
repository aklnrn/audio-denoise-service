# Микросервис для шумоподавления речевых аудиоданных

Микросервис для шумоподавления речевых аудиоданных на базе **DeepFilterNet**. Сервис принимает аудио- и видеофайлы через REST API, выполняет предварительную обработку и асинхронный ML-инференс через Celery + Redis, после чего предоставляет обработанный WAV-файл.

Дополнительно реализован экспериментальный модуль оценки влияния шумоподавления на качество распознавания речи с использованием **faster-whisper** и метрики **WER (Word Error Rate)**. Для сравнения предусмотрена обработка аудио с помощью **DeepFilterNet** и **Demucs**.

> **Примечание:** исходные аудиозаписи, эталонные тексты, транскрипции и результаты экспериментов из рабочего проекта не включены в репозиторий, поскольку содержат конфиденциальные данные. Код сервиса и оценочного пайплайна доступен полностью и может быть запущен на собственных данных.

---

## О проекте

Задача проекта — разработать сервис, который позволяет отправить аудио- или видеофайл через HTTP API и получить его версию с уменьшенным уровнем шума без необходимости самостоятельно запускать ML-модель или выполнять предварительную конвертацию файла.

Сервис построен по асинхронной архитектуре:

```text
Клиент
   │
   ▼
FastAPI
   │
   ├── валидация файла
   ├── предварительная обработка
   └── постановка задачи в очередь
              │
              ▼
          Redis
              │
              ▼
       Celery Worker
              │
              ▼
         DeepFilterNet
              │
              ▼
       обработанный WAV
```

Асинхронная обработка позволяет не удерживать HTTP-запрос во время выполнения ресурсоёмкой операции шумоподавления.

## Основные возможности

* загрузка аудио- и видеофайлов через REST API;
* проверка поддерживаемого формата файла;
* извлечение аудиодорожки из видео;
* конвертация аудио в WAV;
* приведение аудио к mono / 16 kHz на этапе предварительной обработки;
* постановка ресурсоёмких задач в очередь Celery;
* асинхронное шумоподавление с использованием DeepFilterNet;
* отслеживание состояния задачи;
* скачивание обработанного аудиофайла;
* контейнеризация компонентов с помощью Docker;
* автоматические тесты для части сервисной логики;
* экспериментальная оценка влияния шумоподавления на качество ASR;
* сравнение результатов DeepFilterNet и Demucs по WER.

## Архитектура

Сервис состоит из трёх основных компонентов.

### 1. API — FastAPI

API отвечает за взаимодействие с клиентом:

* принимает загружаемый файл;
* проверяет его расширение;
* выполняет предварительную обработку;
* создаёт задачу на шумоподавление;
* возвращает `task_id`;
* предоставляет endpoint для проверки статуса;
* предоставляет endpoint для скачивания результата.

### 2. Worker — Celery

Celery Worker выполняет ресурсоёмкую ML-обработку отдельно от API.

Worker:

1. получает задачу из очереди;
2. загружает подготовленный WAV;
3. запускает DeepFilterNet;
4. сохраняет обработанный файл;
5. возвращает информацию о результате.

### 3. Redis

Redis используется как брокер сообщений и backend для хранения результатов Celery-задач.

Таким образом, HTTP API и ML-инференс разделены между отдельными процессами.

## Pipeline обработки

### 1. Загрузка и валидация

Клиент отправляет аудио- или видеофайл на:

```text
POST /tasks/denoise
```

Сервис проверяет расширение файла и безопасно обрабатывает его имя.

Поддерживаемые форматы:

**Аудио:**

* WAV
* MP3
* OGG
* FLAC
* M4A

**Видео:**

* MP4
* MOV
* AVI
* MKV

### 2. Предварительная обработка

Для входного медиафайла используется **FFmpeg**.

Выполняются:

* извлечение аудиодорожки из видео;
* конвертация в WAV;
* преобразование в mono;
* установка частоты дискретизации 16 kHz.

Подготовленный файл сохраняется во временное локальное хранилище входных данных.

### 3. Асинхронная обработка

API создаёт Celery-задачу и передаёт её через Redis Worker'у. API сразу возвращает `task_id`, не ожидая завершения ML-инференса.

### 4. ML-инференс

Worker загружает подготовленный WAV, при необходимости приводит частоту дискретизации к 48 kHz и выполняет шумоподавление с помощью **DeepFilterNet**.

Результат сохраняется в WAV.

### 5. Получение результата

Статус задачи доступен через:

```text
GET /tasks/{task_id}
```

Готовый файл можно скачать через:

```text
GET /tasks/{task_id}/download
```

## API

### `POST /tasks/denoise`

Загружает аудио- или видеофайл и создаёт задачу на шумоподавление.

Пример запроса:

```bash
curl -X POST \
  -F "file=@audio.wav" \
  http://localhost:8000/tasks/denoise
```

В ответ возвращается идентификатор созданной задачи.

### `GET /tasks/{task_id}`

Возвращает состояние задачи Celery.

Используется для отслеживания выполнения асинхронной обработки.

### `GET /tasks/{task_id}/download`

Возвращает готовый обработанный WAV-файл.

### `GET /health`

Проверка доступности API:

```text
GET /health
```

Пример ответа:

```json
{
  "status": "ok"
}
```

## Оценка качества

Помимо самого сервиса, в проекте реализован отдельный экспериментальный pipeline для оценки влияния шумоподавления на распознавание речи.

Идея эксперимента:

```text
Исходное аудио
      │
      ├──────────────► ASR ──────────► WER
      │
      ├── DeepFilterNet ─► ASR ─────► WER
      │
      └── Demucs ────────► ASR ─────► WER
```

Для каждого варианта аудио выполняется автоматическая транскрибация с помощью **faster-whisper**.

Полученный текст сравнивается с эталонной транскрипцией с использованием метрики **WER (Word Error Rate)**.

### WER

WER позволяет оценить, насколько результат распознавания отличается от эталонного текста.

В общем виде:

```text
WER = (S + D + I) / N
```

где:

* `S` — количество замен слов;
* `D` — количество удалений;
* `I` — количество вставок;
* `N` — количество слов в эталонном тексте.

Эксперимент позволяет оценивать не только изменение звучания аудио, но и то, как шумоподавление влияет на последующее распознавание речи.

### Сравниваемые варианты

В эксперименте рассматриваются:

1. исходное аудио;
2. аудио после DeepFilterNet;
3. аудио после Demucs.

Примечание: результаты экспериментов на рабочих аудиоданных не публикуются. Оценочный скрипт предназначен для запуска на собственных аудиофайлах и эталонных текстах.

## Запуск

Создать локальный `.env` на основе `.env.example`:

```bash
cp .env.example .env
```

Запустить сервис:

```bash
docker compose up --build
```

После запуска:

* API: http://localhost:8000
* Swagger UI: http://localhost:8000/docs

## Запуск оценки качества

Оценочный pipeline рассчитан на работу с пользовательскими данными.

Для запуска необходимо подготовить:

* собственный аудио- или видеофайл;
* соответствующий эталонный текст;
* запущенный сервис.

Установить зависимости оценки:

```bash
python3 -m pip install -r requirements-eval.txt
```

После запуска API можно использовать:

```bash
python3 scripts/transcribe_compare.py \
  --api-url http://localhost:8000 \
  --input-file path/to/audio.wav \
  --reference-file path/to/reference.txt
```

Скрипт выполняет полный цикл:

1. отправляет файл в API;
2. ожидает завершения задачи;
3. получает результат DeepFilterNet;
4. запускает обработку Demucs;
5. выполняет транскрибацию вариантов аудио;
6. рассчитывает WER;
7. сохраняет результаты локально.

Реальные аудиозаписи, эталонные тексты, транскрипции и результаты экспериментов из рабочего проекта в репозиторий не включаются.
